Cloudflare Pages hosting **attaches to a JavaScript app that Aspire already models** — it is not a standalone "point at a folder" resource. You add your frontend with the standard Aspire JavaScript APIs, then mark it for Pages.

## Deploy a frontend to Pages

<Tabs syncKey="apphost-language">
<TabItem label="C#">

```csharp
builder.AddViteApp("web", "../web")        // or AddNodeApp / AddJavaScriptApp
    .PublishAsCloudflarePages();
```

</TabItem>
<TabItem label="TypeScript">

```typescript
await builder.addViteApp('web', '../web').publishAsCloudflarePages();
```

</TabItem>
</Tabs>

- **`aspire run`** → the app runs as its normal dev server (e.g. Vite).
- **`aspire deploy`** → the app's build runs, then the output is uploaded with `wrangler pages deploy`. The Pages project is created if it doesn't exist.

## Options

<Tabs syncKey="apphost-language">
<TabItem label="C#">

```csharp
builder.AddViteApp("web", "../web")
    .PublishAsCloudflarePages(options =>
    {
        options.ProjectName = "my-site";     // defaults to a sanitized resource name
        options.OutputDirectory = "dist";    // build output dir (Vite default)
        options.Branch = "main";             // production branch
        options.BuildCommand = "npm run build";
        options.SkipBuild = false;           // set true if the output is already built
    });
```

</TabItem>
<TabItem label="TypeScript">

```typescript
await builder.addViteApp('web', '../web').publishAsCloudflarePages({
    configure: async options => {
        await options.projectName.set('my-site');
        await options.outputDirectory.set('dist');
        await options.branch.set('main');
        await options.buildCommand.set('npm run build');
        await options.skipBuild.set(false);
    }
});
```

</TabItem>
</Tabs>

## Talking to your API

Inject the API's URL so the frontend can call it:

<Tabs syncKey="apphost-language">
<TabItem label="C#">

```csharp
var api = builder.AddProject<Projects.Api>("api")
    .WithHttpEndpoint(name: "http")
    .PublishAsCloudflareContainer()
    .WithCustomDomain("api.example.com", "your-zone-id");

builder.AddViteApp("web", "../web")
    .WithEnvironment("VITE_API_URL", api.GetEndpoint("http"))
    .PublishAsCloudflarePages();
```

</TabItem>
<TabItem label="TypeScript">

```typescript
const api = await builder.addProject('api', '../Api/Api.csproj')
    .withHttpEndpoint({ name: 'http' })
    .publishAsCloudflareContainer()
    .withCustomDomain('api.example.com', 'your-zone-id');
await builder.addViteApp('web', '../web')
    .withEnvironment('VITE_API_URL', api.getEndpoint('http'))
    .publishAsCloudflarePages();
```

</TabItem>
</Tabs>

The build receives resolved `WithEnvironment` values in publish context. Endpoint references use the target's custom domain (`https://api.example.com` here), not a local dev-server URL. A referenced endpoint must have a Cloudflare target and custom domain; otherwise provide its production URL explicitly. The default `workers.dev` placeholder is not an account-qualified production address.

In the frontend, read `import.meta.env.VITE_API_URL` and `fetch` from it. Configure the API's CORS policy for the site's origin.

:::caution
Vite embeds `VITE_*` variables in browser assets; those values are public. Never use these variables for API tokens, passwords, R2 credentials or other secrets. Build tools can also print environment values: redact output before sharing it.
:::

## Requirements

- **wrangler** installed — see [How wrangler authenticates](../../getting-started/wrangler/).
- API token with *Cloudflare Pages: Edit* — see [API Tokens](../../getting-started/api-tokens/).

## Custom domains

<Tabs syncKey="apphost-language">
<TabItem label="C#">

```csharp
var zone = builder.AddDeploymentParameter("zone-id");
var host = builder.AddDeploymentParameter("web-hostname");

builder.AddViteApp("web", "../web")
    .PublishAsCloudflarePages()
    .WithCustomDomain(host, zone);
```

</TabItem>
<TabItem label="TypeScript">

```typescript
const zone = await builder.addDeploymentParameter('zone-id');
const host = await builder.addDeploymentParameter('web-hostname');
await builder.addViteApp('web', '../web')
    .publishAsCloudflarePages()
    .withCustomDomainParameters(host, zone);
```

</TabItem>
</Tabs>

Custom domains require *DNS: Edit* and *Zone: Read* on the relevant zone, and the [Zone ID](../../getting-started/account-and-zone-ids/).
